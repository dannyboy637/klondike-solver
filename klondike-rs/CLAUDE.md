# klondike-rs — AlphaZero Klondike Solitaire (Pure Rust)

## Commands
- Check: `cd klondike-rs && cargo check`
- Build: `cd klondike-rs && cargo build --release`
- Test all: `cd klondike-rs && cargo test --all`
- Test crate: `cd klondike-rs && cargo test -p klondike-core`
- Lint: `cd klondike-rs && cargo clippy -p klondike-core --all-targets -- -D warnings` (use `-p` to skip tch-rs if LIBTORCH not set)
- Format: `cd klondike-rs && cargo fmt --all -- --check`
- Format fix: `cd klondike-rs && cargo fmt --all`

## Phase Completion Checklist (MANDATORY — run at end of every phase)
1. **Cargo gate**: run ALL three in order, fix any failures before proceeding:
   ```bash
   cd klondike-rs && cargo fmt --all
   cargo clippy -p <crate> --all-targets -- -D warnings
   cargo test -p <crate>
   ```
   For phases touching multiple crates, test each. Use `--all` when LIBTORCH env is set.
2. **Doc updates** — evaluate each, skip if nothing notable:
   - `memory/rust-session-log.md` — ALWAYS add entry (date, phase, what happened, bugs found)
   - `memory/MEMORY.md` — ALWAYS update phase status and next action
   - `memory/rust-current-context.md` — update ONLY if state changed (new findings, open questions, blockers)
   - `klondike-rs/CLAUDE.md` — update ONLY if new conventions, gotchas, or build quirks discovered (e.g., "hidden.len() includes topmost card", "tch 0.23 not 0.17")
3. **Commit** if user requests it

## Conventions
- Error handling: `anyhow` for binaries, `Result<T, E>` with descriptive errors for library crates
- No `.unwrap()` in library crates; `.expect("reason")` only for true invariants
- Propagate errors with `?`; add context with `.context("what failed")`
- Avoid unnecessary `.clone()` — restructure ownership instead, especially in hot paths (MCTS loop, encoding, self-play)
- Prefer `&str` over `String` in function args, `&[T]` over `Vec<T>` when not consuming
- Define struct/trait signatures first, implement methods second
- Use `for` loops with mutable accumulators over complex iterator chains (easier to debug, add logging)
- Explicit `match` arms over wildcards — catch new variants at compile time

## Architecture
5-crate workspace: klondike-core (env/encoding/actions) -> klondike-search (MCTS/PIMC) -> klondike-nn (tch-rs model) -> klondike-eval (stats/benchmark) -> klondike-train (buffer/selfplay/pipeline/CLI)
Lonelybot is a direct path dependency — no PyO3, no FFI overhead.

## Windows Build (PC — RTX 4060 Ti, Ryzen 5700X)
- **MUST use batch scripts** that call `vcvarsall.bat x64` — Git Bash `/usr/bin/link.exe` (GNU coreutils) shadows MSVC linker
- Batch scripts in repo root: `build.bat`, `test.bat`, `train.bat`
- Python 3.12 venv (NOT 3.14 — too new for PyTorch)
- Key env vars: `LIBTORCH_USE_PYTORCH=1`, `LIBTORCH_BYPASS_VERSION_CHECK=1`
- PATH must include: `.venv\Scripts`, `.cargo\bin`, `.venv\Lib\site-packages\torch\lib`
- **CUDA**: Fixed. `ensure_cuda_loaded()` in `inference.rs` force-loads `c10_cuda.dll` + `torch_cuda.dll` before tch init. `auto_device()` returns `Cuda(0)` with RTX 4060 Ti.

## macOS Build (MacBook — M4 MPS)
- `LIBTORCH_USE_PYTORCH=1 DYLD_LIBRARY_PATH=../.venv/lib/python3.14/site-packages/torch/lib`
- MPS device detected and working with PyTorch 2.10

## Gotchas (discovered during implementation)
- `hidden.len(pos)` includes topmost hidden card — face-down count = `max(0, hidden.len(pos) - 1)`
- Pile position normalization must use full pile length (hidden + visible), not just visible cards
- `cargo clippy --all-targets` fails without LIBTORCH env — use `-p <crate>` to skip tch-rs crates
- Upstream lonelybot has 2 `unused_must_use` warnings — these are not our code, ignore them
- tch 0.23 required (not 0.17) for PyTorch 2.10 compatibility
- **Lonelybot `Hidden::shuffle_all()` no longer exists** at current submodule commit — use `shuffle()` instead (same behavior: global shuffle across all piles)
- `PileVec = ArrayVec<Card, 13>` — from `lonelybot::standard`
- **Weight loading**: Python `.pt` (pickle) is NOT compatible with tch-rs `VarStore::load()`. Use `.safetensors` format instead — `VarStore::load()` auto-detects by extension.
- **tch-rs path naming**: `vs / "blocks" / "0" / "fc1"` (NOT `vs / "blocks.0"` — panics because `.` is treated as path separator)
- **tch-rs `sum_dim_intlist`**: takes `&[-1i64][..]` (slice), not `&[-1i64]` (array ref)
- **tch-rs `backward_step_clip`**: requires `&mut self` on Optimizer (not `&self`)
- **DYLD_LIBRARY_PATH for tests**: must be absolute path, not relative (cargo test changes cwd)

## Testing
- Unit tests in same file (`#[cfg(test)] mod tests`)
- Integration tests in crate `tests/` directory (e.g., `crates/klondike-core/tests/`)
- Encoding parity test (vs Python) is the single most critical test — `crates/klondike-core/tests/encoding_parity.rs`
- NN parity test loads Python weights, compares forward pass — `crates/klondike-nn/tests/nn_parity.rs`
- Parity reference data generated by Python: `crates/klondike-core/tests/parity_data.json`, `crates/klondike-nn/tests/nn_parity_data.json`
- Fixed-seed deterministic tests for MCTS reproducibility
